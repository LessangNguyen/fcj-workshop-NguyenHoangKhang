# 5.1. Workshop Overview & AWS Architecture

Clinical problem statement, 5 core modules of MediMind Clinical AI, target 3-tier AWS VPC architecture in ap-southeast-1, and cost estimation.

## 5.1.1 — Clinical Problem & 5 Core Modules of MediMind Clinical AI

MediMind addresses tertiary hospital overcrowding and unsafe ad-hoc health lookups through five integrated clinical modules:

| Module | Key Source Files | Capabilities & Dataset Scale |
| --- | --- | --- |
| 1. Clinical Triage & Double Guardrails | `core/triage.py`, `core/chat/chat_service.py` | 3-tier risk stratification (Green/Yellow/Red), negation & unaccented Vietnamese handling, 115 emergency alerts, blocks self-prescribing antibiotics. |
| 2. Prescription OCR Reconciliation | `core/ocr/pipeline_orchestrator.py`, `reconciliation_service.py` | Vision LLM (`qwen/qwen3.8-27b` via Groq 4-Key Pool Failover), field-by-field verification, dosage mismatch warnings, and per-user medication reminders. |
| 3. Grounded Hybrid Medical RAG | `core/chat/rag_service.py`, `ingest.py` | Combines BM25 + ChromaDB vector search indexing **364 verified medical documents** (MedlinePlus NIH & Ministry of Health protocols). |
| 4. Personalized Clinical Nutrition | `core/nutrition/nutrition_meal_planner.py`, `nutrition_rules.py` | BMR/TDEE survey synced from user profile, multi-condition & 12-allergen fail-closed filtering across **2,500 Vietnamese dishes**. |
| 5. Pre-visit Summary & Booking | `core/routers/appointments.py`, `facilities.py`, `notifications.py` | Structured pre-visit intake summary, map lookup, and booking across **2,144 healthcare facilities** (1,505 HCMC + 639 Hanoi) with email confirmation. |

## 5.1.2 — Target 3-Tier AWS VPC Architecture (ap-southeast-1)

Workloads are isolated across three network tiers (`Public` → `Private App` → `Private DB`), protected at the edge by AWS WAF and served over HTTPS via Amazon CloudFront.

- **Flows 1–2 (Edge HTTPS :443):** User traffic traverses AWS WAF (OWASP Top 10, SQLi, XSS, Rate Limit) and Amazon CloudFront, which caches `/static/*` at edge locations.
- **Flows 3–4 (Ingress & ALB):** Dynamic `/api/*` requests enter via Internet Gateway to the Internet-facing Application Load Balancer spanning 2 Public Subnets.
- **Flow 5 (Isolated App Tier `:8000` — Multi-AZ ASG):** ALB load-balances internally across **2 `t3.small` EC2 nodes** in `Private App Subnets A & B` (no Public IP, managed by `medimind-asg`), pulling images from ECR, loading secrets from Secrets Manager via IAM Role, using KMS-encrypted `20 GB gp3` EBS + Dual-AZ EFS, and backing up to S3 via **S3 Gateway Endpoint**.
- **Flow 6 (Isolated DB Tier `:5432`):** EC2 connects to Amazon RDS for PostgreSQL 16.16 in Private DB Subnets with zero Internet routing.
- **Flows 7–9 (Dual-AZ Outbound via 2 NAT Gateways):** External API calls (Groq 4-Key Pool, Google OAuth 2.0, Gmail SMTP, Google Maps API) route out independently through **2 NAT Gateways** in `Public Subnet A` (`AZ-1a`) and `Public Subnet B` (`AZ-1b`).

## 5.1.4 — Live Deployment Scope & Custom Domain Rationale (Route 53 & ACM)

This Workshop deploys the full **3-tier Multi-AZ infrastructure** live in `ap-southeast-1`: **6-subnet VPC (2 AZs)**, **2 independent NAT Gateways (`AZ-1a` & `AZ-1b`)**, **S3 Gateway Endpoint**, **Dual-AZ Auto Scaling Group (`medimind-asg`) running 2 `t3.small` EC2 nodes (`2 Healthy` on ALB)**, **Dual-AZ Amazon EFS**, **RDS PostgreSQL 16.16**, **S3 Backup**, **ECR + CodeBuild**, **3 Secrets Manager entries**, **Global AWS WAF (`us-east-1`, 4 rules)**, **CloudFront HTTPS**, **CloudWatch (Log Group + 5 Alarms + SNS)**, and **AWS Budgets (`$20/month`)**.

- **Rationale for Amazon Route 53 & AWS Certificate Manager (ACM):** During architecture design, the team planned for a custom branded domain and therefore included **Route 53** (`Hosted Zone` & DNS routing, estimated at `~$0.90/month`) and **ACM** (free public TLS certificates `$0`) in the target architecture. During hands-on Workshop deployment, to avoid purchasing a commercial domain (`.com` `~$14/year`) solely for an internship demo, the live deployment uses **Amazon CloudFront's built-in HTTPS domain and TLS certificate (`https://d2typ9pphzk4as.cloudfront.net`)** protected by **AWS WAF**—preserving full end-to-end HTTPS encryption while allowing drop-in `CNAME` + `ACM` attachment whenever a production domain is attached.
- **Database Cost Optimization During Demo (`RDS Single-AZ` vs `Multi-AZ`):** `medimind-pg-db` (`db.t4g.micro`, `20 GB gp3`, KMS encrypted) is deployed inside a Multi-AZ `DB Subnet Group` spanning both Private DB Subnets (`10.0.21.0/24` & `10.0.22.0/24`). Single-AZ mode is kept during the Workshop demo to avoid doubling RDS cost (`$20.76` vs `$42.24/month`) and can be promoted to Multi-AZ Standby with a single AWS CLI command.
